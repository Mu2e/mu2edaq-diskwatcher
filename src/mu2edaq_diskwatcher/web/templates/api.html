EndpointReturns
Peers: ?peers=1

Every list endpoint returns this instance's own entries by default. Adding ?peers=1 to /api/status, /api/state, /api/space, /api/sizes or /api/entries brings in the diskwatcher instances named under peers: in the configuration.

peers One record per configured peer: label, url, status (ok, error, pending, disabled), error, version, hostname, fetched_at/fetched_age_s, last_ok/last_ok_age_s, stale, that peer's entries filtered the way the endpoint filters local ones, and a summary of just those entries.
aggregate The endpoint's summary recomputed over local entries plus every peer whose status is ok, with local (local count) and peers (connection counts). Entries retained from an unreachable peer are shown under it with stale: true but are not counted here.
peer, peer_url Added to every entry that came from a peer. /api/entries?peers=1 folds peer entries into the flat list; &peer=LABEL keeps only one peer's.

Federation is one hop: a peer is asked for its own entries only, so two instances may list each other without looping, and a peer's states are shown as it evaluated them, not re-derived here. An instance recognises itself by instance_id and refuses a peer URL that resolves back to it.

Compatibility of /api/status

/api/status always returns files, total, stale, ok and poll_interval, and every element of files always carries at least these keys:

path, label, delay, kind, remote, ssh_host, mtime, mtime_str, age_s, age_str, delay_str, stale, missing, error, disk_total, disk_used, disk_free, disk_pct, disk_total_str, disk_free_str

Keys are added, never removed or retyped. The one exception, introduced with free-space and file-size monitoring: delay is null for an entry that opts out of staleness monitoring. Prefer /api/state for new integrations.

Entry fields
FieldMeaning
watch_state ok, stale, missing, or unmonitored (no delay: configured).
space_state GOOD, WARNING, CRITICAL, FULL, MISSING (path unreachable) or UNKNOWN (path exists but the filesystem could not be measured). null when the directory has no space: block.
size_state As above, plus EMPTY for a zero-length file. null when the file has no size: block.
space_rank, size_rank, watch_rank Numeric severity, higher is worse. Sort on these rather than re-deriving an ordering from the state names.
*_trigger Which threshold fired: warning, critical, full, empty, or null.
*_reason One human sentence explaining the state, e.g. "93.1 GiB free ≤ critical 465.7 GiB".
*_limits Thresholds resolved to bytes. Percentages are resolved against the filesystem capacity at poll time.
*_limits_str Thresholds exactly as written in the YAML.
space_limits_ordered false when the resolved thresholds do not escalate (warning > critical > full), which makes some alarm states unreachable.
disk_pct / disk_free_pct Percent of capacity used / percent still free.
size_pct / size_pct_ref Size as a percentage of the named threshold — the largest one configured for that file.
config_errors Problems found in this entry's configuration, such as an unparseable threshold.
Examples
# every disk in a CRITICAL or FULL state
curl -s localhost:{{ settings_port }}/api/space \
  | python3 -c 'import json,sys; print([e["path"] for e in json.load(sys.stdin)["entries"]
                if e["space_state"] in ("CRITICAL","FULL")])'

# every zero-length file
curl -s "localhost:{{ settings_port }}/api/entries?state=EMPTY"

# is the poller alive?
curl -s localhost:{{ settings_port }}/api/health | python3 -m json.tool

# which peers are unreachable?
curl -s localhost:{{ settings_port }}/api/peers \
  | python3 -c 'import json,sys; print([p["label"] for p in json.load(sys.stdin)["peers"]
                if p["status"] != "ok"])'

# every CRITICAL volume here or on any peer
curl -s "localhost:{{ settings_port }}/api/entries?peers=1&monitored=space&state=CRITICAL"
